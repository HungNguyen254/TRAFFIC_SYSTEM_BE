# E2E Encrypted AI Chatbot API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an authenticated, end-to-end encrypted AI Chatbot API powered by Google Gemini API with cross-device session synchronization and zero-knowledge database storage in FastAPI.

**Architecture:** Client and server use dual-envelope key management. The client generates an AES-256 session key (`K_session`), encrypts it with its password-derived User Master Key (UMK) for cross-device synchronization, and securely negotiates it with the backend via X25519 ECDH handshake. Messages are encrypted client-side using AES-256-GCM, decrypted in server RAM to query Google Gemini API with multi-turn history, encrypted before responding, and persisted in the database strictly as ciphertexts and nonces.

**Tech Stack:** Python 3.12+, FastAPI, SQLModel (PostgreSQL/SQLite), `cryptography` (X25519, AESGCM, HKDF, PBKDF2), `httpx` (async Gemini API integration), SlowAPI rate limiting, Pytest.

**Spec:** [docs/superpowers/specs/2026-11-15-e2e-chat-bot-design.md](file:///home/PageNguyen/Projects/BE/docs/superpowers/specs/2026-11-15-e2e-chat-bot-design.md)

## Global Constraints
- Python 3.12+ compatibility with existing FastAPI and SQLModel project structure.
- All chat endpoints require JWT authentication using existing `get_current_user` dependency.
- All stored messages and session keys in database must be strictly ciphertexts and nonces; no plaintext prompts, AI responses, or raw keys stored in DB.
- Inner decrypted payload standard: `{"content": "<text>", "timestamp": "<ISO8601>"}`.
- Gemini API key must be kept secret on the server via `GEMINI_API_KEY` environment variable.
- Tests must pass using `.venv/bin/pytest`.

## Review Focus
1. Nonce reuse failure: Sending two messages with the identical nonce must fail or each message must mandate a cryptographically random 12-byte nonce.
2. Cross-device key restoration: A second client instance with the same password and user salt must successfully decrypt `session_key_enc_user` and read historical messages.
3. Tampered ciphertext detection: Corrupted or altered ciphertext/tag must fail authentication check (AESGCM `InvalidTag`) and return HTTP 400 without crashing the server.
4. Unauthorized session access: A user requesting or posting messages to a `session_id` owned by another user must receive HTTP 404 or 403.
5. Missing or invalid Gemini API key: Backend must return a graceful HTTP error (502 Bad Gateway or 503) rather than uncaught 500 exceptions when Gemini API fails.

### Task 1: Cryptographic Utility Module (`app/core/crypto.py`)

**Files:**
- Create: `app/core/crypto.py`
- Test: `tests/test_crypto.py`

**Interfaces:**
- Produces:
  - `generate_x25519_keypair() -> tuple[x25519.X25519PrivateKey, str]` (returns private key and base64 public key)
  - `derive_shared_secret(private_key: x25519.X25519PrivateKey, peer_public_key_b64: str) -> bytes`
  - `derive_key_hkdf(shared_secret: bytes, salt: bytes, info: bytes, length: int = 32) -> bytes`
  - `derive_user_master_key(password: str, salt_b64: str) -> bytes` (PBKDF2HMAC SHA-256)
  - `encrypt_aes_gcm(key: bytes, plaintext: bytes) -> tuple[str, str]` (returns base64 ciphertext, base64 nonce)
  - `decrypt_aes_gcm(key: bytes, ciphertext_b64: str, nonce_b64: str) -> bytes`
  - `encrypt_server_secret(secret_data: bytes) -> tuple[str, str]` (uses `settings.JWT_SECRET_KEY`)
  - `decrypt_server_secret(ciphertext_b64: str, nonce_b64: str) -> bytes`

### Task 4: Chat Schemas & Endpoints (`app/schemas/chat.py`, `app/api/v1/endpoints/chat.py`)

- Create: `app/api/v1/endpoints/chat.py`

**Interfaces:**
- Consumes: `app.core.security.get_current_user`, `app.core.crypto`, `app.services.gemini_service.GeminiService`, `app.models.chat`
- Endpoints:
  - `GET /api/v1/chat/user-salt` -> `{ "encryption_salt": "base64..." }`
  - `POST /api/v1/chat/handshake` -> accepts `HandshakeRequest(client_public_key, session_key_enc_user, session_key_nonce_user, encrypted_session_key_for_server, server_handshake_nonce)`, returns `HandshakeResponse(session_id, server_public_key)`
  - `POST /api/v1/chat/message` -> accepts `SendMessageRequest(session_id, ciphertext, nonce)`, decrypts in RAM, fetches previous turns context, calls `GeminiService`, encrypts AI reply, saves both to DB, returns `MessageResponse(session_id, ciphertext, nonce)`
  - `GET /api/v1/chat/sessions` -> returns list of user's sessions with encrypted title and `session_key_enc_user`
  - `PATCH /api/v1/chat/sessions/{session_id}` -> updates encrypted title
  - `GET /api/v1/chat/sessions/{session_id}/messages` -> returns list of messages (ciphertext, nonce, role, created_at)
  - `DELETE /api/v1/chat/sessions/{session_id}` -> deletes session and cascade messages
